03The brief

One comment, nine coordinates.

Every comment ships as a structured brief the agent can act on directly — not a screenshot with a sentence attached.

selector
Names the exact DOM element. No screenshot, no description needed.
snapshot
The element’s own opening tag, attributes and text — capped short, deliberately shallow so the model isn’t drowned in child markup.
appliedCssRules
The rules that actually win — not the full computed dump. Answers “why is it blue?” before the agent has to ask.
computedStylesclassesparentInfo
Disambiguate the structure when the selector alone is generic.
routepageUrlpageTitle
Identifies which screen or view to open.
viewportdeviceTypedevicePixelRatio
Turns “broken on mobile” into a reproducible condition.
PageContextSnapshotopt-in · bug reports
Console errors and failed or slow network requests, captured at the moment of the issue.
sourcePathwhen source mapping is on
The source file behind the element, when mapping is enabled — tiered by what the build exposes.
language
The BCP-47 tag the comment was detected in — so translation is automatic, in both directions.

05The contrast

The same request, with and without coordinates.

Without Pointer

  • “The checkout feels broken on my phone” — no element, no repro, no viewport.
  • A developer guesses the file, the rule, the screen.
  • An AI agent loops through blind exploration of the codebase before it touches the right file.
  • The fix lands as a screenshot reply in a thread — nothing links back to a commit.

With Pointer

  • Click the element — the brief already carries the selector, the winning CSS, the route, the viewport.
  • The agent starts at the selector and the winning rule, not at src/.
  • Mechanical edits and translation delegate to a cheaper model; judgment stays on the premium one.
  • Every applied comment links back to its commit URL — committed, never pushed.

06The margin

Why teams point instead of screenshot.

time

Context attached to the click

No meeting to reconstruct what “broken on mobile” meant — the brief already says where, what, and at which viewport.

cost

Fewer clarification loops

The ask arrives with its coordinates attached, so threads stay short and meetings turn into reviews.

tokens

Fewer premium-model tokens

The agent starts at the selector and the winning CSS rule. Mechanical edits and translation go to a cheaper model, so the expensive one spends its tokens on the parts that need judgment.

queue

One organized queue

Tagged, triaged, per project and environment — not screenshots in five channels.

08The kit

Small to install. Wide to work with.

install

Two-line install

<script src="https://api.pointer.moamen.work/widget.js" defer></script>
<pointer-feedback project="acme-web" server="https://your-api"></pointer-feedback>

A script tag and a custom element. No SDK, no build step, no framework lock-in.

tenancy

Multi-project, multi-tenant

Workspaces with isolation enforced server-side. Every comment is tagged by project, environment, and stakeholder.

isolation

Shadow-DOM widget

The widget lives in its own shadow root — your styles can’t leak in, its styles can’t leak out. Any framework, any stack.

extension

Browser extension

The same element-level comments on pages you don’t host — client sites, staging behind login, third-party tools.

          12On the record

          Fair questions, straight answers.

          “An AI edits my code?”

          It commits, never pushes. You review every diff before it lands, and each applied comment carries its commit URL — the change traces back to the ask.

          “What exactly do you capture?”

          Element-level DOM metadata only: selector, winning CSS, route, viewport. Never form values, cookies, localStorage, or request bodies.

          PrivacyData & self-hosting

          “Which AI tool do I need?”

          Any. The queue is plain HTTP, so whatever agent you already use can pull it — and if your tool speaks MCP, there’s a server for that too. No lock-in.

          “Is my data stuck with you?”

          No. Pointer self-hosts: the API plus a Postgres database you own. Your data stays yours.
