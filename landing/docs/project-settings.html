Project Settings

Environments

What is a workspace environment?

A workspace environment (like local, prod, or staging) determines where a project's URLs live. This is not the same as the Local/Staging/Production tag you select on a specific comment (which is just a label for that comment).

How to enable an environment?

Administrators can enable or disable environments from the global environment catalog or create custom ones for their workspace. When an environment is disabled, you cannot add new URLs to it, and existing URLs will be treated as if they don't exist (the widget won't be blocked, but it won't be explicitly mapped).

How to assign a URL per environment?

In your project settings, you can define exactly one URL for each enabled environment. This tells Pointer where your app lives for that specific environment.

Default Environments

By default, new projects will have their URL placed in the local environment. If you had an existing project whose URL was previously assigned to the legacy default environment, it has now been automatically migrated to the local environment.
