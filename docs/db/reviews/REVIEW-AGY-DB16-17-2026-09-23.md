## DB-16: Screenshot purge

## DB-17: Demo as a product

**Finding 1 (BLOCKER): Backfill data-loss risk (over-reaches to real workspaces)**
- **Section:** §3.2 Migration 2 `BackfillWorkspacesDemoState`
- **Evidence:** `JOIN workspace_memberships m ON m.user_id = u.id AND m.owner_id = w.id ... WHERE u.is_demo = true`. If a demo user (who has `u.is_demo = true`) was invited to an existing, real workspace, this join will match that real workspace and overwrite its `demo_expires_at` with the demo user's TTL. This would turn the real workspace into a demo workspace that gets hard-deleted at expiry.
- **Amendment:** Restrict the backfill to the specific workspace originally provisioned for that demo user by leveraging the legacy `users.owner_id` column (which recorded the demo workspace ID at creation). Add `AND u.owner_id = w.id` to the `WHERE` clause:
```sql
UPDATE workspaces w
SET demo_expires_at           = u.expires_at,
    demo_extended_at          = CASE WHEN u."DemoExtended" THEN COALESCE(u.updated_at, u.created_at) END,
    demo_comment_cap_override = u."DemoCommentCapOverride",
    demo_ttl_hours_override   = u."DemoTtlHoursOverride"
FROM users u
JOIN workspace_memberships m ON m.user_id = u.id AND m.owner_id = w.id AND m.left_at IS NULL AND m.deleted_at IS NULL
WHERE u.is_demo = true
  AND u.owner_id = w.id
  AND u.deleted_at IS NULL
  AND u.expires_at IS NOT NULL
  AND w.deleted_at IS NULL
  AND w.demo_expires_at IS NULL
  AND w.demo_converted_at IS NULL;
```
Also update the §9 step 1 pre-check query to include `AND m.owner_id = u.owner_id`.

**Finding 2 (HIGH): Race condition in `DemoCleanupService` could delete a just-converted workspace**
- **Section:** §3.5 Expiry, warning, cleanup
- **Evidence:** `DemoCleanupService.cs:43-54` materialises `expiredIds` into a list, then loops and calls `HardDeleteAsync`. If a user converts their workspace (via `UpgradeAsync`) while the sweep is in its 30-second delay or iterating, `HardDeleteAsync` will blindly delete the now-real workspace, destroying the user's data (because `TenantService.HardDeleteAsync` trusts the caller and does not check demo status itself).
- **Amendment:** In `DemoCleanupService.SweepAsync` step (2), inside the `foreach` loop and its fresh scope, re-fetch the workspace to confirm it is still an expired demo immediately before calling `HardDeleteAsync(pid)`.
```csharp
var stillExpired = await uow.Workspaces.IgnoreQueryFilters()
    .AnyAsync(w => w.Id == pid && w.DemoExpiresAt != null && w.DemoExpiresAt < DateTime.UtcNow);
if (!stillExpired) continue;
```

**Finding 3 (MEDIUM): Ambiguity in multi-tenant contexts for `ExtendAsync` and `UpgradeAsync`**
- **Section:** §3.3 Read-switch and dual-write & §3.6 Public entry, self-service extension
- **Evidence:** The design resolves the workspace by looking for "the one whose workspace has DemoExpiresAt != null". If a demo user is invited to a second demo workspace, finding "the one" is ambiguous. Both endpoints (`POST /api/demo/upgrade` and `POST /api/demo/extend`) are `[Authorize]`, meaning they receive a tenant-scoped JWT.
- **Amendment:** Pass the current workspace ID (via `_currentUser.TenantId.Value` or equivalent `User.GetTenantId()`) down from the controller to `ExtendAsync(Guid callerPublicId, Guid workspaceId)` and `UpgradeAsync(Guid callerPublicId, Guid workspaceId, UpgradeDemoRequest request)`. Filter by `w.Id == workspaceId` inside the methods so the operations strictly target the current session's workspace.

**Verdict: IMPLEMENT WITH AMENDMENTS**
