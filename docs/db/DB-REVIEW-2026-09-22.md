## 6. Evolution readiness — "can we add X without touching user data?"

| Change class | Safe pattern in this codebase | Precedent |
|---|---|---|
| New per-row attribute | Nullable column or `HasDefaultValue`/`HasDefaultValueSql`; one `AddColumn`; no backfill needed. | `20260917230734_AddCommentLanguage`, `20260917220722_AddReplyIsAi`, `20260912125359_AddProjectCaptureTextContent` |
| New structured bag on an existing row | `jsonb` via `JsonColumn.ConfigureJsonColumn(col, "'{}'"|"'[]'")` (tolerant parse, canonical write, comparer) — `Infrastructure/Mappings/JsonColumn.cs:67-75`. Owned `ToJson` only when the shape is fixed and queried as a unit (`Comment.Element`). Cap sizes at the validator; document the shape in the entity doc-comment. | R4-01 `comments.custom_fields`, `workspace_settings.comment_field_definitions` |
| New tenant-scoped entity | `: BaseEntity`, `OwnerId` (NOT NULL unless a global bucket is *designed*), mapping with explicit `HasColumnName`, query filter copied from the `Project` shape (`AppDbContext.cs:77`), `HasIndex(OwnerId)`, a `TenantQueryFilterTests`-style test proving tenant B sees nothing. After DB-03: FK `owner_id → workspaces(id)`, and the entity added to the `HardDeleteOrder` list (the reflection test fails otherwise). | `WorkspaceSetting` (R4-01 A2), `ProjectBuild` (`20260912193031`) |
| New relationship | Real FK with explicit `OnDelete`; EF adds the index. State the cascade in the mapping comment. | `ProjectBuildMapping.cs:27`, `PageContextSnapshotMapping.cs:45`, `CommentMapping.cs:48-49` (SetNull) |
| Rename column/table | **Never in one migration.** Expand (add new) → dual-write in code → backfill migration (batched) → switch reads → contract (drop) in a later release. Rebranding plan §11.1 already forbids renames of schema objects. | Anti-precedent: `ProjectPerEnvironmentActivation` did all three in one `Up()` |
| Split a table (e.g. workspace out of users) | Additive table + backfill + FKs first (DB-03 stage A); move columns later (stage B) with dual-read. | DB-03 |
| Type change / narrowing | New column of the new type + backfill + swap reads + drop old; widening (`WidenUsageEventSource`, `20260917234138`) is safe in place. | `20260917234138` |
| Enum value | Enums are stored as `int` (`CommentStatus`, `EnvironmentTag`, `NotificationType`, `SuggestionStatus`, `BuildSource`). Append values; **never renumber or reuse** an int. | `Domain/Enums/*` |
| Backfill | Separate migration or `AdminSeeder` step; guarded `WHERE`; for tables past ~100 k rows: batched by `id` range in a loop outside one transaction (see DB-RULES). | `20260915163653:44-46`, `AdminSeeder.cs:92-118` |

**Recommended order:** DB-01 → DB-02 → DB-04 → DB-05 → DB-03 → DB-06 → DB-07 → DB-08.
DB-01 and DB-02 first because everything after them is a migration under auto-apply. DB-04/05 are
small warm-ups that exercise the rehearsal loop before the structural DB-03. DB-06 wants DB-03's
`workspaces` FK in place so the orphan pre-check has one root. DB-07 is independent and can go any
time after DB-01. DB-08 last; it is the only one that needs product numbers.

Not endorsed (one line each, so they are not re-raised):

- **Global EF soft-delete query filter** — 162 `IgnoreQueryFilters()` calls would silently start bypassing soft-delete too; the fix is bigger than the problem at this stage. Re-evaluate after DB-03 when the filter set is reworked.
- **Switching `BaseEntity.Id` to `uuid`/`bigint`** — `int` identity gives 2.1 B rows per table; the comments table would need ~60 years at 1 k/day. Not a launch risk.
- **Row-level security in Postgres** — the app enforces tenancy with a single-connection-role model; RLS would require `SET LOCAL` per request and a second rollout of every filter. Application filters + DB-03 FKs are enough for the current threat model.
- **Merging `workspace_settings` into `workspaces`** — keep the satellite; it already has a converter and tests. DB-03 gives it an FK instead.
- **Renaming any table/column for the rebrand** — rebranding plan §11.1 already forbids it; nothing in the schema carries the brand.
- **Converting `projects.tech_stack`/`ai_tools_used`/`environment_selector_role_ids` to `jsonb`** — only when the columns are next touched (S-11).
- **Indexing `author_id`** — no query needs it yet (I-4).
