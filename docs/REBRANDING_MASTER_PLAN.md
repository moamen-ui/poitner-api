## Architecture Overview: Two Distinct Rebranding Layers

Before modifying any files, the executing agent must understand that this codebase has two separate branding layers:

1. **Technical Source Rebrand (Static):**
   * Renaming C# namespaces (`Pointer.*` → `${NEW_BRAND_PASCAL}.*`), assemblies, solution files, and `.csproj` projects.
   * NPM client packages (`@moamen-ui/pointer-*` → `@moamen-ui/${NEW_BRAND_SLUG}-*`).
   * Custom element tag name (`<pointer-feedback>` → `<${NEW_BRAND_SLUG}-feedback>`).
   * Script bundle filenames (`pointer.js` → `${NEW_BRAND_SLUG}.js`, `pointer.css` → `${NEW_BRAND_SLUG}.css`).
   * Environment variable prefixes (`VITE_POINTER_*` → `VITE_${NEW_BRAND_UPPER}_*`).
   * Configuration keys (`"Pointer": { ... }` → `"${NEW_BRAND_PASCAL}": { ... }`).
   * Git repository URLs and Docker container/service names.

2. **Runtime Branding Subsystem (Dynamic / Database-Driven):**
   * The system already features a dynamic white-labeling engine (`IBrandingService`, `BrandingController`, `GET /api/branding`).
   * Display names, taglines, primary theme colors, logos, favicons, and URLs (`app`, `demo`, `docs`, `landing`) are stored dynamically in the `app_settings` database table and consumed at runtime by the dashboards, browser extension popup, and landing page.
   * Do NOT hardcode brand strings into dashboard UI views that already fetch from `/api/branding`.
   * The seed defaults in `BrandingService.cs` (`DefaultProductName`, `DefaultTagline`, `DefaultUrlApp`, etc.) MUST be updated to the new brand defaults so new deployments boot with the new brand out-of-the-box.

## Phase 1: Negative Guardrails (CRITICAL: DO NOT RENAME)

Automated search-and-replace will corrupt the application if standard web and browser APIs are renamed. The executing agent **MUST STRICTLY EXCLUDE** the following tokens:

### 1. CSS & Tailwind Utilities
* `cursor: pointer` / `cursor-pointer` (Mouse pointer on interactive elements)
* `pointer-events: none` / `pointer-events-auto` / `pointer-events: auto` (Event hit-testing rules)
* Any class matching `(pointer-events|cursor-pointer)`

### 2. Native DOM & Web APIs
* `PointerEvent` (W3C Pointer Events interface)
* `pointerdown`, `pointerup`, `pointermove`, `pointerenter`, `pointerleave`, `pointerover`, `pointerout`, `pointercancel`
* `setPointerCapture`, `releasePointerCapture`, `hasPointerCapture`
* Media queries: `@media (pointer: fine)`, `@media (pointer: coarse)`

### 3. C# / CLR Language Primitives
* Unsafe memory pointer constructs: `IntPtr`, `UIntPtr`, `*` (unsafe pointers), `fixed` statements.
