**A. npm name — partial concede.** Not a blocker for an experimental CLI; it's a blocker on letting the name get baked into files you don't control. The pain isn't docs (server prints those) — it's the on-disk contract `init` writes into customer repos: `.pointer/` dir + `POINTER_*`/`VITE_POINTER_*` env names + gitignore lines (every checkout, CI cache, teammate clone); `.mcp.json` entries saying `npx pointer mcp` (§24 — that file is committable); the `<pointer-feedback>` tag + `window.__pointerEmbedded` in customer index.html (Program.cs:297-305); and npm reality — no unpublish after adoption, so plan for a permanent deprecate-stub package that prints/forwards the new command. Minimal recipe for painless rename: (1) post-rebrand code dual-reads old env/dir/tag names forever (~10 lines), (2) stub package never dies, (3) treat repo-landing names as frozen API from today — brand-neutral where possible (you already did this once: `data-component-source`, not `data-pointer-source`). So: "land the name first" downgrades to "freeze the on-disk contract before init ships." That's the trap you were missing.

**D. §17 advisory flag — hold, drop it entirely.** Feedback *is* instructions; "make it stop ignoring the saved filter" and "delete this section" are your median content, so instruction-likeness fires on legitimate comments constantly — a badge that's usually wrong trains reviewers to ignore it. Better 2 hours: flag objective, low-FP patterns only — secret-shaped strings (`sk-`, `AKIA`, `ghp_`, long base64), `<script>`, `curl … | sh` — labeled "possible payload/secret." That protects something real.

**E. §31 — concede first-year, hold the sequencing.** The mechanism is genuinely cheap *where the widget loads*: `CommitUrl` exists (Comment.cs:21) → add CommitSha + a `(projectId, sha, firstSeenAt)` table; the Phase 4 plugin stamps `data-pf-build`; any authed widget load marks that sha's comments deployed. Prod coverage needs a beacon-when-disabled mode, which has its own privacy questions. So: ship it with Phase 4 (same stamp), staging/preview first; keep §10-at-commit-time as the primary loop — deployed is enrichment, not replacement.
