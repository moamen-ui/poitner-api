## Flake notes

- The privacy fixture is the **only** commenting surface for these ids — never `e2e-alpha`/`e2e-beta` (ground truth + R1-05 fixture); `ensure-project` in `beforeAll`, never per test.
- `capture-config` is read once at boot: every scenario that PATCHes the toggle must `page.reload()` + re-`waitForResponse('**/capture-config')` before the next widget comment, or the widget still holds the old flag.
- Compare against the literal three-codepoint string `'•••'` (U+2022 ×3) — never a regex `.+` placeholder.
- Do not replace `.fill()` with `setAttribute('value', …)` — that flips the scenario from property-typed to attribute (rule A.1's first branch) and silently weakens step 5.
- Toggle restore in `finally` is part of PASS criteria (R3-04-03 step 6) — a leaked `false` breaks R3-04-04's text-kept expectation on the next run and H-02's two-run determinism.
- Comment cadence: each widget submission waits for `#pf-popover-host` toBeEmpty (10 s, `widget.spec.ts:86` pattern) — no fixed sleeps; these scenarios issue ≤ 6 comments, far under the 30/min/user policy.
