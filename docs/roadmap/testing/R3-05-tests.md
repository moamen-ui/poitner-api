## Covers

Acceptance criteria of R3-05: AC-1 (shared styles light+dark, ≤ 1 screen per section on desktop, no horizontal scroll at 390 px) → R3-05-03 (+ honest strings in R3-05-01) · AC-2 (every factual claim maps to shipped code; no unresolved `TODO(founder)` except region/provider) → R3-05-01 step 7 (the claims **spot-check** itself is human review — Not covered) · AC-4 (`privacy.html` and `data.html` agree; effective date bumped) → R3-05-01 step 8 · AC-5 (footer links in `index.html` + `v2/index.html`, both languages) → R3-05-01 steps 2–3 + 9 · Execution-doc "Checks" (`html-validate`, link check, Lighthouse a11y ≥ 95) → R3-05-04 + R3-05-02. AC-3 (DX-UX-CX-PLAN hold list) and AC-6 (VM deploy `curl -I` → 200) → manual (Not covered).

## Preconditions

- R3-04 and R1-06 merged (the page's form-value/mask/API-key claims must be true — execution doc Prerequisites); if either is unmerged the corresponding strings are removed from the page, and R3-05-01 steps 4–5 assert only the strings that remain (Decision: the string list below is the post-merge target; the spec reads the expected list from a constant that R3-04/R1-06 merge commits flip — never state what shipped code does not do).
- `landing/data.html`, refreshed `landing/privacy.html`, footer links in `landing/index.html` (+ i18n maps `:572`/`:628`) and `landing/v2/index.html` exist (R3-05 tasks 1–3).
- Serving (Decision — replaces the execution doc's `python3 -m http.server 8099` with the harness stack): `node e2e/scripts/serve-dir.mjs landing <PORTS.landing>` with **new** `PORTS.landing = 8099` (Decision: keep 8099, the execution doc's number, but move it into the `constants.mjs` port registry per 00-HARNESS §2 — nothing hard-codes a port elsewhere). Started/killed by `run-e2e.sh` (PR + nightly) with the existing trap pattern.
- No personas (all flows anonymous); no seed dependency beyond the stack being up — the landing phase may run before or after seed (it never touches the API; `data.html` is static, only asset/link URLs are fetched).

- `DX-UX-CX-PLAN.md` hold-list entry (AC-3) and the VM deploy `curl -I https://<landing>/data.html` → 200 (AC-6) — manual, post-merge (a real deploy is §8's manual tier by definition).
- `pointer-init.md`/dashboard help cross-links to `/data.html` (§C) — R3-04's doc/dashboard surface; dashboard link lives in the pointer-dashboard repo (`DASH-` prefix).
- No unit tests exist for this doc (execution doc Tests: "No unit tests") — nothing to exclude.

## Flake notes

- The landing phase is order-independent (never touches the API/DB) — safe to run in PR tier before seed finishes if needed, but keep the standard §8 order unless the budget forces it.
- serve-dir on 8099 uses `--strictPort`; the only other 8099 consumer is the execution doc's ad-hoc python server — never run both (the harness path replaces it).
- R3-05-03 step 2 compares computed colors — assert inequality only (exact hex values would churn with styling PRs); screenshots (`toHaveScreenshot`) are the visual-regression layer, add them only if landing churn demands it (§7: never MCP).
- The v2 Arabic assertion compares the exact i18n map value `البيانات والاستضافة الذاتية` — copy changes must update the spec constant in the same PR (single-constant list, like the step-4 string list).
