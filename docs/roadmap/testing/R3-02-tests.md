## Preconditions

- Seed complete (`credentials.json`, `keys.json`); personas `USERS.developer` (DEV — init/doctor) and `TENANT_OWNER` (WA — apply prompt).
- Prerequisite docs merged: R1-02 (init, non-interactive flags), R1-01 (gitignore `!.pointer/stack.json`), R2-01 (`apply --plan`), R3-01 (fixture `e2e/fixture-app/vite-react/`).
- Fixture additions (Decision — R3-01 task 13b's fixture as written has no CSS custom properties, but AC-1 requires `cssVars.names ∋ --brand`; this suite owns the addition): `e2e/fixture-app/vite-react/src/styles/globals.css` with `:root { --brand: #4f46e5; --brand-contrast: #ffffff; --radius-md: 8px; }`; `tailwind.config.ts` with `theme.extend.colors = { primary: …, secondary: …, muted: … }`, `borderRadius = ['sm','md','lg']`, `fontFamily = ['sans','mono']`.
- `CLI_ENTRY` built (§6). Shared argv helper `e2e/scripts/lib/init-args.mjs` exports `INIT_ARGS`/`INIT_ENV` (R1-02's non-interactive `init --yes` with the DEV key from `state/keys.json`, server `http://localhost:8090`, project `e2e-alpha`; Decision: exact flag spellings are owned by R1-02-tests — the helper is the single place a rename lands).
- Fixture copy helper: `lib/vite-fixture.mjs` `copyFixture({ into: repo })` (R3-01's copy path without the build; `npm ci` cache shared under `state/vite-react/`).
- **Stack target — Decision:** `frontend`/`backend` are **write-once-if-empty**, *not* idempotent/append-if-new: `Application/Services/Implementation/ProjectService.cs:715-718` ignores every later POST once `TechStack` is non-empty (only `aiTools` grows). Consequences this suite must respect: (a) the **first** stack POST against a project wins for the whole DB lifetime, so any scenario whose detection differs must use its own throwaway project key; (b) `INIT_ARGS` (project `e2e-alpha`) may be used **only** by the react-fixture scenarios; the plain-HTML "no tokens" case in R3-02-04 step 4 must target a fresh `e2e-r302-empty-<runId>` key, or it can lock alpha's stack to the HTML detection and make R3-02-03 step 4 / R3-02-05 step 3 (`frontend ∋ 'react'`) fail until the next `down -v`.

## Flake notes

- `doctor --refresh-stack` in R3-02-02 step 4 runs against a dead server URL — keep the env rewrite + restore inside one test so a failure cannot leak `http://localhost:9` into later scenarios.
- The recording proxy must die in `finally` (`--strictPort`); it is the only listener allowed on 4179. Register `PORTS.recorder = 4179` in the harness §2 table (`PORTS` does not exist in `e2e/scripts/lib/constants.mjs` yet — the harness introduces it).
- `apply --plan` depends on seeded ReadyToApply comments — this spec runs in the cli phase (after seed, per §8 phase order); never create the temp repos under `e2e/state/fresh/` (fresh-app owns that tree).
- Repeat `POST /stack` calls are **write-once-if-empty** for `frontend`/`backend` (`ProjectService.cs:715-718`; only `aiTools` appends) — do not "clean up" the stack between runs, and never let a differently-detected fixture POST to `e2e-alpha` (see Preconditions): the first writer silently wins and the later assertion fails with no error anywhere.
