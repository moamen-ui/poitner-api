# R2-04-tests — In-app notifications + author verify loop

Harness: [`00-HARNESS.md`](00-HARNESS.md). Execution doc: [`../execution/R2-04-inapp-notifications.md`](../execution/R2-04-inapp-notifications.md).

## Covers

AC-1 (applied-by-another → exactly one `CommentApplied` for the author, in list + `unread-count`) → R2-04-01/04 · AC-2 (badge within 70 s without reload; opening list clears it) → R2-04-01/03 · AC-3 (👎 + note → `Status=Open`, reply, back in `status=1` list) → R2-04-02 · AC-4 (quick-access author can verify; cannot PATCH status — guard intact) → R2-04-05 · AC-5 (no leaks across tenants **or users within a tenant**) → R2-04-04 · AC-6 (`just test`, widget typecheck/build) → CI, not a scenario.

## Preconditions

- Seed complete; personas: CL (`CLIENT`, scoped to `e2e-alpha`), WA (`TENANT_OWNER` — **the applier persona**: the account whose PATCH sets `Comment.AppliedBy`; `CommentReopened` is addressed to `AppliedBy` specifically, not to "staff" in general), QA (`USERS.tester`), DEV (`USERS.developer`), DP (`USERS.deputy`), TB (`TENANT_B_OWNER`).
- **Prerequisite docs merged:** R1-07 (mailpit service + `lib/mail.mjs` — the `assertNoMail` steps below depend on it), R2-04.
- Fixture: `node e2e/fixture-app/serve.mjs alpha **4181**` (widget phase, trap-killed by `run-e2e.sh`). **Port 4173 is reserved for the `smoke` fixture** (`run-e2e.sh:23`, the only page honouring `?project=` — R2-05 needs it), so the alpha fixture gets its own `PORTS.alpha = 4181`; all URLs below are `http://localhost:4181/`.
- Widget specs import `preAuthWidget(page, token, user)` from `e2e/widget/lib/auth.ts` (the 3-arg helper extracted from `widget.spec.ts:41-51` — R2-00 task; it sets localStorage `pointer_token`/`pointer_user` **and** sessionStorage `pointer_visible`, which is what makes the toolbar render at all: a context without it shows only the launcher, `element.ts:161-163,649-655`).
- **Register `waitForResponse('**/capture-config')` before the action that triggers it** — for a pre-authed context the request fires during `_boot`/`init` (`element.ts:266-267`), so register it before `page.goto`.
- **Environment filter:** `fetchComments()` always requests `?environment=${this.environmentInt}` (`element.ts:618`) and the alpha fixture mounts `environment="staging"` (env 2). Any scenario asserting on a `.pf-card` for a comment created with `environment: 1` or `3` must first switch the widget: `await widget.locator('#pf-env').selectOption('production')` (the pattern at `widget.spec.ts:77,96`; `#pf-env` renders because the fixture sets no `fixed-environment`).
- **Widget poll knob (binding, harness §9):** the widget reads `window.__POINTER_CONFIG__.notifyPollMs` (default 60000); every notifications spec injects `addInitScript(() => { window.__POINTER_CONFIG__ = Object.assign(window.__POINTER_CONFIG__ || {}, { notifyPollMs: 1000 }); })` **before** `preAuthWidget`'s init script. With the 1 s poll the badge lands in ~1–2 s; the Playwright `expect.poll` timeout of **70 s is a ceiling, never a sleep**.
- **Widget selectors (Decision — pinned here so R2-04 task 9 and the specs agree):** header button `#pf-notify` with badge span `#pf-notify-badge`; dropdown host `#pf-notify-list`; verify buttons on own applied cards `button[data-act="verify-ok"]` / `button[data-act="verify-no"]`; note input `#pf-verify-note` + submit `#pf-verify-submit`. **Collapsed-state badge:** the execution doc's AC-2 names the *launcher* badge (`../execution/R2-04-inapp-notifications.md:76` → `templates.ts:135`, `.pf-launcher-badge`), which today renders an open-comment count (`element.ts:650`); R2-04 task 9 extends it to carry the unread count in `--pf-notify`. R2-04-01 asserts **both** surfaces.
- **Tier split (Decision, per harness §9):** PR tier asserts the **API surface** (R2-04-04/05); the badge/list/verify **widget** scenarios are nightly (they depend on the poll).
- Email is held (§32): every notify step also asserts no mail left the building.

## Flake notes

- Never assert the badge synchronously — always `expect.poll` with the 70 s ceiling; with `notifyPollMs: 1000` the wait is ~1–2 s. **Never a fixed sleep** (harness §9).
- R2-04-01 → 02 → 03 are one ordered chain in one browser fixture (same comment, cumulative unread state); do not parallelise across workers.
- R2-04-05 reuses seeded C8 — after it runs, C8 has `verifiedAt` set; specs later in the run must not re-verify it.
- The reply in R2-04-03 must come from DEV (not WA) so the recipient is CL, not the applier — ReplyAdded goes to the comment author when replier ≠ author.
