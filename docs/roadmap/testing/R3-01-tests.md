## Covers

Acceptance criteria of R3-01: AC-1 (two clean clones → identical `entries`) → R3-01-05 · AC-2 (`POST /builds` 400/403/404/repeat) → R3-01-06 · AC-3 (prod build stamps every root, Fragment all roots, component-only root none — **and bundle behaviour unchanged**) → R3-01-01 (stamping) + R3-01-00 (unchanged-markup diff) · AC-4 (`manifest.json` gitignored) → R3-01-01 step 3 · AC-5 (widget comment carries the hash; `pointer get --json` → `resolvedSource`) → R3-01-01 · AC-6 (rename → stale warning + prev hint **and apply proceeds via fallback search**) → R3-01-02 · AC-7 (`apply` stores `commitSha`; `status --deployed` marks ancestors only) → R3-01-04 · AC-8 (widget beacon once, `✓ live`) → R3-01-03 · AC-9 (old comments never deployed) → R3-01-03 step 9 / R3-01-06. AC-10 (unit + dashboard) is unit-level, not covered here.

## Preconditions

- Seed complete (`credentials.json`, `keys.json`); personas: `USERS.developer` (DEV — CLI/plugin), `USERS.tester` (QA — widget), `TENANT_OWNER` (WA — apply/`status --deployed`), `CLIENT` (CL — quick-access negative), `TENANT_B_OWNER` (TB — cross-tenant negative).
- **Project isolation — Decision:** this suite never writes to `e2e-alpha`. It creates its own project **`e2e-r301`** (WA token, 409-tolerant creator copied from `e2e/widget/widget.spec.ts:22-36`) and every comment, PATCH and `/builds` report below targets it. Rationale: `e2e/scripts/probe-visibility.mjs:51-70` asserts **exact set equality** of `e2e-alpha`'s comment ids against `state/expected.json`, and `e2e/widget/widget.spec.ts:1-3` records that alpha is deliberately never touched by the browser suite; the `--with-ai` phase and `scripts/audit.mjs` run *after* this suite. Cross-tenant negatives still use `e2e-gamma` (TB).
- Prerequisite docs merged: R2-01 (`apply`, `get --json`, `status`), R1-01 (gitignore), R3-01 itself.
- Fixture `e2e/fixture-app/vite-react/` (R3-01 task 13b): React + Vite + Tailwind; components `Card` (single root `<div class="card">`), `PlanList` (Fragment → `<h2>` + `<ul>`), `TrackedCard = memo(function TrackedCard(p){ return <Card {...p}/> })` — **Decision:** the HOC case must wrap an **inner function declared in this file**, because `execution/R3-01-vite-plugin-manifest.md:50` stamps "the inner function"; a bare `memo(Card)` over an imported `Card` has no inner function here and would silently prove nothing. `Shell` (returns only `<Card/>`, no host root), plus a `<form>` with `<input id="email" type="email">` and a `<button id="cta">`. `vite.config.ts` uses `pointerSource({ enabled: process.env.VITE_POINTER_SOURCE === 'true' })` from `pointer-feedback/vite` via a `file:../../../cli` dependency. `index.html` embeds the widget via `/embed.js?project=e2e-r301&environment=staging` from `http://localhost:8090`.
- Build helper `e2e/scripts/lib/vite-fixture.mjs`: `buildFixture({ dir, buildSha, enabled = true })` runs `npm ci` (once, cached in `state/`), then `VITE_POINTER_SOURCE=<enabled> npm run build` inside a **temp git repo** (`lib/git.mjs tempRepo()` — the plugin reads `git rev-parse --show-toplevel` and `HEAD`; the fixture is copied there so the hash's `repoRelativePath` is `src/components/…`), returns `{ distDir, manifest, repo }`. Serves `dist/` with `serve-dir.mjs <dist> 4175`.
- Env: `CLI_ENTRY` set (§6 of the harness). Project `e2e-r301` created and active for Staging.

## Flake notes

- `buildFixture` runs `npm ci` once per suite (cached under `state/vite-react/node_modules`); the build itself ~10–20 s — nightly tier only.
- R3-01-03 counts `/builds` calls with `page.route` **before** `goto`; the widget posts fire-and-forget, so wait for the response, then `expect.poll` for 3 s to prove no second call. **Accepted weakness:** absence-of-a-second-call cannot be proven by polling — a call at 3.1 s would pass. The 3 s bound is a deliberate exception to harness §9's no-fixed-window rule; the stronger alternative (export a module-level `__pfBuildReports` counter for `page.evaluate`) is deferred to R3-01 if this ever flakes.
- Serve the fixture on **4175** only; kill via the `run-e2e.sh` trap.
- `builds` policy is 30/min per user: R3-01-06 issues ≤ 12 requests per user — safe; never loop it.
- R3-01-04 needs `git config user.email` in the temp repo (feeds `appliedByLabel`).
