# R2-05-tests — Passwordless quick-access invites (link-copy delivery)

Harness: [`00-HARNESS.md`](00-HARNESS.md). Execution doc: [`../execution/R2-05-quick-access-invites.md`](../execution/R2-05-quick-access-invites.md).

## Covers

AC-1 (invite returns `magicLink` `<AppUrl>?pointer_invite=<43-char token>`, no email by default) → R2-05-01/08 · AC-2 (link signs the client in, no password; `pointer_invite` gone on success **and** failure; never persisted in `pageUrl`/`route`) → R2-05-01/02/03 · AC-3 (`login-with-invite` under the `login` policy 60/min/IP, not `signup`, and not touching the deliberately-unlimited `POST /api/auth/login`) → R2-05-06 · AC-4 (password login fails for the provisioned client) → R2-05-05 · AC-5 (rotate + revoke invalidate the link) → R2-05-03/04 · AC-6 (raw token nowhere in DB) → unit, see below · AC-7 (`just test`, widget build) → CI.

## Preconditions

- Seed complete; personas: WA (`TENANT_OWNER`), CL (invited clients — one per scenario, `qa-cl-<runId>-<n>@example.com`, all QuickAccess/Client role scoped to the fixture project), SA (`SUPER_ADMIN` — settings toggle).
- **Seed change shipped with R2-05 (mandatory, harness §3):** `e2e/scripts/seed.mjs` drops the password overwrite + password login (`seed.mjs:104-106`). New flow: after `POST /api/admin/invites { roleId, email, expiresInDays: 7, projectId: alpha.id }` the response's `magicLink` is captured; seed extracts `pointer_invite=<token>`, redeems it via `POST /api/auth/login-with-invite { token }`, and stores `credentials.json.client = { email, displayName, inviteToken, magicLink, token, user }` (token/user from the redemption). H-03's client login switches to `login-with-invite` accordingly (see H-tests H-03 step 1). No `PATCH /api/admin/users/{id} { password }` anywhere.
- Fixture project: WA creates `e2e-qa-invite` (`POST /api/admin/projects { key: 'e2e-qa-invite', name: 'E2E QA Invite' }`, 409 → reuse) and `PATCH /api/admin/projects/{id}` `{ appUrl: 'http://localhost:4173/?project=e2e-qa-invite' }`. **Decision:** the smoke page (`serve.mjs smoke 4173`, `smoke/index.html`) honours `?project=` (the `E2E_SMOKE_PROJECT_KEY` mechanism in `widget.spec.ts:19-20`), so the magic link keeps the project override as an existing query param and the API appends with `&`: expected `magicLink === 'http://localhost:4173/?project=e2e-qa-invite&pointer_invite=<token>'`. Assert `GET /api/public/projects/e2e-qa-invite/widget-status?origin=http%3A%2F%2Flocalhost%3A4173` → `active: true` once per run.
- Client role id: `get('/api/admin/roles', { token: wa })` → `find(r => r.name === 'Client')` (same resolution as `seed.mjs:74-79`).
- **Prerequisite docs merged:** R1-07 (mailpit service + `lib/mail.mjs` — R2-05-07/08 depend on it), R1-05 (owns the `login` rate-limit policy), R2-05.
- Mail: `lib/mail.mjs` (`clear`, `awaitMessage`, `assertNoMail`, `extractLink`); mailbox cleared before every mail scenario.
- **Widget reveal:** redemption calls `saveAuth` → `init()` → `renderChrome()`, but `_collapsed` is still true in a fresh context (nothing set `sessionStorage.pointer_visible`), so `renderChrome()` emits **only** the launcher (`element.ts:161-163,649-655`). Every signed-in assertion below therefore clicks `widget.locator('#pf-launcher')` first; `#pf-add` / `#pf-user` do not exist before that.
- **429 isolation:** R2-05-06 runs in the final, isolated phase (`run-e2e.sh --429`, optional `docker compose -p e2e-429` with shifted ports) — always **last** (harness §8/§9). The bucket it poisons is the per-IP **`login`** policy, which R1-05 applies to `login-with-key` and `login-with-invite` **only** — never to `POST /api/auth/login`, which carries no limiter and is kept that way by a binding unit test (`Tests/AuthRateLimitingTests.cs:21-29` `Login_IsNotRateLimited`). Consequence: the phases that burn `login-with-key` — **apply (R2-01), MCP (R2-02), every CLI scenario** — must all run **before** the `--429` phase, or their CLI logins start failing.

## Flake notes

- **429 ordering is absolute:** R2-05-06 must be the final phase of the run; 61 rapid `login-with-invite` calls poison the per-IP **`login`** bucket for a minute. That bucket is shared with **`login-with-key`**, which every CLI/MCP scenario uses (`pointer.sh:65`, the CLI's JWT handshake) — so the apply, MCP, doctor and init phases must all precede it. Password logins (`POST /api/auth/login`) are unaffected: that endpoint is deliberately unlimited.
- Each invite uses a unique email per run (`<runId>`) — mail assertions (R2-05-07/08) never match a previous run's message, and re-inviting a used address would 409.
- The magic link appends with `&` because `AppUrl` carries `?project=` — if the project override moves out of the URL, update the regex in R2-05-01 step 2 accordingly.
- The widget's invite exchange has a 3 s timeout (R2-05 task 8) — on CI jitter the *success* path is asserted via `capture-config`, never by racing the exchange; keep `waitForResponse` on the follow-up request, not on `load`.
