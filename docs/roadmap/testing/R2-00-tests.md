# R2-00-tests — Fresh-app init E2E + white-label CI job

Harness: [`00-HARNESS.md`](00-HARNESS.md). Execution doc: [`../execution/R2-00-e2e-fresh-app-whitelabel.md`](../execution/R2-00-e2e-fresh-app-whitelabel.md).

## Covers

AC-1 (`--fresh` green for all stacks) → R2-00-01…04 · AC-2 (vite+static init→first-comment ≤ 300 s, seconds printed, ≤ 1 retry) → R2-00-01/02 step 8 · AC-3 (angular **and `next`** assert the exact hand-off message + no `index.html`/`app/` edit) → R2-00-03/04 · AC-4 (whitelabel: human CLI output contains `Acme Review`, zero leak-regex matches; widget innerText, modal title, `title`/`aria-label` pass) → R2-00-05/06/08 · AC-5 (Task 0 leak fix — `grep '"Open Pointer feedback"' templates.ts` empty) → R2-00-08 step 4 · AC-6 (CI matrix + whitelabel job green on dispatch) → CI wiring, not a scenario row · AC-7 (branding restored, `GET /api/branding` → `Pointer`) → R2-00-07 · **AC-8…12 (§52 rebrand rehearsal)**: AC-8 served surfaces emit the mock domain → R2-00-09 · AC-9 widget under the mock domain shows the new brand → R2-00-10 · AC-10 e-mails carry the new name + domain → R2-00-11 · AC-11 teardown restores branding *and* origin → R2-00-12 · AC-12 TLS variant emits `https` → R2-00-13 (manual). The scenarios R2-00's Tests section merely *hosts* from other docs are cross-referenced under "Not covered here".

**Two dimensions, kept separate.** R2-00-05/06/08 swap only the **name** (`Acme Review`) and prove no
literal leaks — a string test. R2-00-09…13 additionally swap the **domain** (`pick-it.test`) and prove
the running product serves, links and mails under it — a routing + emission test. They share the
branding mechanism but not the window: the name-only window closes (R2-00-07) before the mock-domain
window opens (R2-00-09), because the two set conflicting `urls.*` values.

## Preconditions

- Seed complete (`state/credentials.json`, `state/keys.json`); personas used: DEV (`USERS.developer`), SA (`SUPER_ADMIN`). Role shorthand per testing-review §3.
- Prerequisite docs merged: R1-02 (`init`), R1-04 (`doctor`), R1-07 (workflow). CLI built: `cd cli && npm run build`; `CLI_ENTRY=node <repo>/cli/dist/cli.js`.
- `e2e/scripts/serve-dir.mjs` exists (R2-00 task 3b) and serves any dir on a port. **Decision:** the branding helpers live at `e2e/scripts/set-branding.mjs` + `e2e/scripts/reset-branding.mjs` (harness §4 layout is binding, superseding the execution doc's `e2e/whitelabel/` paths); both log in as `SUPER_ADMIN` and `PUT /api/admin/branding` (super-admin-gated, `Admin/BrandingController.cs:19`) using `BrandingWriteDto` field names `productName`, `tagline`, `urls.app`.
- Branding defaults for restore (`BrandingService.cs:9-17`): `productName "Pointer"`, `tagline "Point at the UI. Ship it with AI."`, `urls.app https://app.pointer.moamen.work`.
- **Widget reveal (binding, harness §9):** a fresh browser context starts collapsed — `element.ts:161-163` sets `_collapsed` unless `sessionStorage.pointer_visible === '1'`, and `renderChrome()` then emits **only** `TPL.launcher` and returns (`element.ts:649-655`). So `#pf-toggle` / `#pf-add` / `#pf-user` / `#pf-env` do not exist until the toolbar is revealed. Every widget step below either uses `preAuthWidget(page, token, user)` (which already sets `pointer_visible='1'`, `widget.spec.ts:41-51`) **or** clicks `widget.locator('#pf-launcher')` first.
- **Shadow-root text:** `widget.locator(':root')` matches nothing inside a shadow root. Use `page.locator('pointer-feedback').innerText()` for whole-widget text sweeps.
- **`preAuthWidget` is a 3-arg, non-exported local** (`e2e/widget/widget.spec.ts:41`). Task (R2-00 spec files): extract it to `e2e/widget/lib/pre-auth.ts` and import the 3-arg form everywhere; every doc below assumes that extraction.
- Fresh projects are created with `enforceAllowedOrigins` default **false**, so the widget renders on any origin; each spec still asserts the gate: `GET /api/public/projects/{key}/widget-status?origin=http%3A%2F%2Flocalhost%3A4174` → `data.active === true`.
- Generators pinned to a minor and run with npm cache present: `npm create vite@6.0 -- --template vanilla-ts`, `npx @angular/cli@20.0 new fresh-ng --defaults --skip-git --skip-install`, `npx create-next-app@15.0 --ts --app --no-eslint --use-npm --yes`.
- Ports: fresh preview **4174** (`--strictPort`); registry in `lib/constants.mjs`. Generated apps live under `e2e/state/fresh/<stack>/` (gitignored). **Both R2-00-01 (`vite preview`) and R2-00-02 (`serve-dir.mjs`) bind 4174 under `--strictPort`, so the fresh-app stacks run strictly sequentially** — one serial phase in `run-e2e.sh` (`workers: 1` for `fresh.spec.ts`), never a parallel matrix on one runner.
- `run-e2e.sh --fresh` / `--whitelabel` flags wrap the phases; **the whitelabel phase always runs `node e2e/scripts/reset-branding.mjs` in a `finally`** (harness §8).
- **Mock-domain rows (R2-00-09…13) — harness §13 is binding.** `E2E_MOCK_DOMAIN=pick-it.test` and `E2E_MOCK_BRAND=PickIt` gate the whole group; unset, `run-e2e.sh` skips the phase and `lib/report.mjs` records five `SKIP` rows with the reason (harness §8). **Decision:** `.test` over `.dev` — `.dev` is HSTS-preloaded in Chrome, so plain HTTP is force-upgraded and unserveable locally (§13.1); the real brand domain may still be `.dev`, since every assertion is on the emitted string and the host routing, not the TLD.
- **Browser rows use the Chromium resolver rule; node rows use a `Host` header — never both for one claim** (§13.2). `e2e/playwright.config.ts:10-13` has no `launchOptions` today; the rule is added there gated on `E2E_MOCK_DOMAIN`, so a normal run is unchanged.
- **`Pointer__PublicUrl` is the emission knob**: `PointerUrlResolver.ResolvePublicUrl` (`API/Extensions/PointerUrlResolver.cs:15-20`) prefers `Pointer:PublicUrl` over the request origin, and it is the single source for `/embed.js` (`Program.cs:288`), the `<POINTER_SERVER>` rewrite (`Program.cs:213-214`) and branding asset URLs (`BrandingController.cs:38`). Set/cleared via `restart-api.mjs`.
- **Frozen names are not part of the rebrand** (§13.3): `pointer-feedback`, `.pointer/`, `POINTER_*`, `pointer_token`, `/pointer.js`. The leak regex `/(?<![-\w])Pointer(?![-\w])/g` already exempts them by construction. A rehearsal row that fails on one of these is the row being wrong.

## Flake notes

- npm scaffolding nondeterminism → pinned **minor** generator versions + npm cache; exactly one whole-stack retry on the 300 s budget (harness §9).
- `vite preview` and `serve-dir.mjs` both use `--strictPort` 4174; started/killed by `run.mjs` `finally` so a failed stack never leaks the port into the whitelabel phase. **The stacks therefore run serially** — never two fresh-app stacks in parallel on one runner.
- Widget boot race: **register** `waitForResponse('**/capture-config')` before the action that triggers it — `fetchCaptureConfig()` runs inside `init()`, which `_boot` calls only when a token already exists (`element.ts:266-267`); in a fresh-login flow it fires from the post-login callback (`element.ts:673`), so a waiter registered afterwards hangs to timeout (`widget.spec.ts:61-62` is the correct pattern).
- The fresh apps inject the widget with `environment=local`, so comments land in env 1 — assert with the unfiltered API list or `environment=1`; in the widget, `fetchComments()` always filters by `environmentInt` (`element.ts:618`).
- Brand-window ordering: R2-00-06/08 contexts must be created **after** the branding PUT (`loadBranding()` runs once per boot, `element.ts:263`).
- R2-00-06/08 must run **inside** the R2-00-05 brand window and before `reset-branding.mjs`; ordering is `run.mjs --brand-check` (CLI) → widget specs → `finally` reset → R2-00-07 assert.
- `next`/`angular` scaffolds are nightly-only (runtime + npm variability); PR runs only execute them when `cli/**` changed.
- **Mock-domain window ordering is strict**: `reset-branding` (R2-00-07) must complete **before** R2-00-09 sets the `pick-it.test` branding — the two windows write the same `brand_url_*` keys, and an overlap makes the leak counts meaningless. Order: whitelabel specs → `finally` reset → R2-00-07 assert → R2-00-09 (restart + brand) → 10 → 11 → `finally` R2-00-12.
- **Two API restarts** (`restart-api.mjs` on entry and exit of the mock-domain window) — that is the whole budget for this phase; harness §8 allows at most 3 per run, and R2-03/R1-04 already claim the others, so the mock-domain phase and the skill-stamp phase must not be scheduled in the same nightly run without re-counting.
- R2-00-11 spends **2 `signup` tokens** of the 5/hour/IP budget (harness §9): `forgot-password` once, `register-invite`-adjacent invite creation once. It therefore runs **before** the `--429` phase and never alongside R1-08's suite, which already consumes 7–10 in its own compose project.
- R2-00-10's context must be created **after** R2-00-09's branding PUT — `loadBranding()` runs once per widget boot (`element.ts:263`), so an earlier context caches `Pointer` and the row fails for the wrong reason (same trap as R2-00-06/08).
- The resolver rule maps **DNS only**; the port is still whatever the URL says. `http://pick-it.test/` (no port) hits :80 and fails — every mock-domain URL carries `:8090` (or `:8443` in the TLS variant).
