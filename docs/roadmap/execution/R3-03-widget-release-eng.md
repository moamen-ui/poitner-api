# R3-03 — Widget release engineering (versioned serving, SRI, size budget, deploy smoke, CSP)

(NEW-3, absorbs §22 + §34 · Release 3 · 3–4 days)

## Goal

`pointer.js` is loaded by every customer page straight from the API; today a bad deploy reaches
all of them at once and nothing measures the widget's weight. After this item: hosts can **pin** a
version with an immutable URL + SRI, the default **latest** path stays self-updating, every build is
described by a committed `pointer.version.json`, CI fails when the bundle exceeds **60 KB gzip** or
the committed artifacts are stale, and a post-deploy smoke script proves the served widget matches
the build. Nonce-strict CSP hosts get a documented, working stylesheet path.

## Out of scope

- Keeping historical builds on the server (a pinned `?v=` that no longer matches serves the current build with `no-cache` — see §A.3; hosts that SRI-pin own the upgrade).
- Minifying `pointer.js` (kept readable on purpose — `web-component/build.mjs:27-29`). Revisit only if the gzip budget is hit.
- Widget kill switch (§40, held) and versioning of `skill.md` (R2-03).
- Extension changes beyond reading `pointer.version.json` (it loads `${server}/pointer.js` — `extension/src/inject-main.ts:92` — and keeps doing so).

## Prerequisites

- None hard. Pairs with **R1-04** (`GET /api/meta` gains `widgetVersion`) and **R1-02** (`init --pin` writes the SRI snippet for static hosts).
- Facts: static serving sets `Cache-Control: no-cache` for `pointer.js`/`pointer.css` only (`API/Program.cs:239-256`); Caddy adds `no-cache, must-revalidate` for `/pointer.js /pointer.css /embed.js /skill.md /api/branding` (`Caddyfile` `@widget` block); build is `web-component/build.mjs` (esbuild IIFE, `BANNER`, unminified; sass → `pointer.css`); sibling asset URLs are resolved from `document.currentScript.src` (`web-component/src/constants.ts:153-162`) — a `?v=` query on the script URL does not affect `new URL('pointer.css', SCRIPT_SRC)`; the stylesheet is a `<link>` appended into the shadow root (`web-component/src/element.ts:186-191`); snapdom (126 KB) is lazy-loaded at capture time (`capture.ts:24-40`) and is **not** in the budget; only `publish-clients.yml` exists under `.github/workflows/`; the Docker image bakes `wwwroot` (`Dockerfile:8-13`).

## Design

### A. URL & cache scheme

| Request | Behaviour | Headers |
|---|---|---|
| `GET /pointer.js` (and `.css`) | **latest** — unchanged | `Cache-Control: no-cache` + ETag (API) / `no-cache, must-revalidate` (Caddy) |
| `GET /pointer.js?v=<hash>` where `<hash>` == current build hash | **pinned, immutable** | `Cache-Control: public, max-age=31536000, immutable` |
| `GET /pointer.js?v=<hash>` mismatch | serve current bytes | `Cache-Control: no-cache`; response header `X-Pointer-Widget-Version-Mismatch: <current>` |
| `GET /pointer.js?v=stable` | **stable channel** = current bytes with 1 h TTL (for hosts that want fewer revalidations without pinning) | `Cache-Control: public, max-age=3600` |
| `GET /pointer.version.json` | build descriptor (§B) | `no-cache` |

`<hash>` = first 12 hex of SHA-256 over the built `pointer.js` bytes (computed by `build.mjs`, stored in §B). CSS uses the same `v` value (one release = one hash); the CSS entry has its own integrity.

**Decision — Caddy:** the `@widget` matcher must not clobber the immutable header: change to
```
@widget {
    path /pointer.js /pointer.css /embed.js /skill.md /api/branding
    not query v=*
}
header @widget Cache-Control "no-cache, must-revalidate"
```
so requests with `?v=` fall through to the API's headers.

### B. `API/wwwroot/pointer.version.json` (generated by `build.mjs`, committed)

```json
{
  "version": "0.1.0",
  "hash": "9f1c2a7b3e4d",
  "builtAt": "2026-09-11T10:40:12Z",
  "files": {
    "pointer.js":  { "bytes": 118765, "gzipBytes": 31240, "integrity": "sha384-…" },
    "pointer.css": { "bytes": 19491,  "gzipBytes": 4210,  "integrity": "sha384-…" }
  },
  "budget": { "pointerJsGzipMax": 61440 }
}
```
`version` = `web-component/package.json` version (bump on every widget-affecting PR — add to the widget checklist in `AGENTS.md`). `GET /api/meta` (R1-04) returns `widgetVersion: <hash>` read from this file at startup.

### C. SRI snippet (static hosts, opt-in)

```html
<script src="https://<server>/pointer.js?v=9f1c2a7b3e4d"
        integrity="sha384-…" crossorigin="anonymous" defer></script>
<pointer-feedback project="…" server="https://<server>" environment="staging"></pointer-feedback>
```
Emitted by `pointer init --pin` (static/Vite `index.html` only) and printed by `pointer doctor --pin-snippet`. `embed.js` stays unpinned (latest). The widget itself must load `pointer.css` with the same `?v=`: in `constants.ts`, propagate the `v` query from `SCRIPT_SRC` to `CSS_URL` (`SNAPDOM_URL` unchanged — snapdom is vendored and rarely changes).

### D. Size budget + artifact freshness (CI)

New workflow `.github/workflows/widget-check.yml` (on PR/push touching `web-component/**` or `API/wwwroot/pointer.*`):
1. `npm ci && npm run typecheck && npm run build` in `web-component/`.
2. `git diff --exit-code -- API/wwwroot/pointer.js API/wwwroot/pointer.css API/wwwroot/pointer.version.json` → fails with "committed widget artifacts are stale — run npm run build".
3. `node scripts/check-budget.mjs` → fails if `files["pointer.js"].gzipBytes > budget.pointerJsGzipMax` (**61 440 B = 60 KB**).
4. Boot-time perf guard: `node scripts/perf-init.mjs` — Playwright loads `e2e/fixture-app/smoke` with the built widget and asserts no long task > 50 ms attributable to `pointer.js` during init (PerformanceObserver `longtask`), retried 3×. **Decision:** warn-only for the first release (annotation), hard-fail once R3 ships.

`build.mjs` computes gzip sizes (`node:zlib.gzipSync`) and integrity (`sha384` base64), writes §B, and **fails the build locally** on budget breach (same rule as CI).

### E. Deploy smoke (`scripts/smoke-widget.sh <server>`)

Checks, each must pass: `GET /pointer.version.json` 200 → `hash`; `GET /pointer.js` 200, first line contains the `BANNER`, SHA-256[0..12] == `hash`; `GET /pointer.js?v=<hash>` returns `Cache-Control: … immutable`; `GET /pointer.css` 200; `GET /embed.js?project=smoke` 200 and contains `pointer-feedback`; `GET /api/branding` 200; `GET /api/meta` `widgetVersion == hash`. Wired into `DEPLOY.md` as the last step (`bash scripts/smoke-widget.sh https://api.<domain>`), and into `e2e/run-e2e.sh` against the local stack.

### F. CSP for nonce-strict hosts

- Allowlist hosts (the common case) are already documented (`pointer-init.md:170-189`): `script-src`, `style-src`, `connect-src`, `img-src` include the server origin — unchanged.
- Nonce-strict `style-src` blocks a runtime `<link>`. **Decision:** in `element.ts` keep the `<link>` first; on its `error` event (or if `document.adoptedStyleSheets` is supported and `link` has not loaded within 1500 ms), `fetch(CSS_URL)` → `new CSSStyleSheet().replace(text)` → `shadowRoot.adoptedStyleSheets = [sheet]`. Constructed stylesheets are not governed by `style-src`; the fetch is covered by `connect-src`, which the host must already allow for the API. Scripts (`pointer.js`, lazy snapdom) still require the origin in `script-src` — no nonce-only solution without host cooperation; document that in `pointer-init.md` ("CSP" subsection) with the two working host configurations.

Serve `/pointer.version.json` with `no-cache`.

## Tests

- **Unit (API, xUnit):** `WidgetCacheHeadersTests` — `/pointer.js` → `no-cache`; `?v=<current>` → immutable; `?v=wrong` → `no-cache` + mismatch header; `?v=stable` → `max-age=3600`; `/pointer.version.json` served. `MetaWidgetVersionTests` — `widgetVersion` equals the file's `hash`.
- **Unit (widget, vitest or node test):** `constants.test.ts` — `CSS_URL` inherits `?v=`; `stylesheet-fallback.test.ts` — link error → adoptedStyleSheets path used (jsdom with a stubbed `CSSStyleSheet`).
- **Build:** `check-budget.mjs` fails on a fixture JSON over budget; `widget-check.yml` fails on stale artifacts (simulate by editing `pointer.js` in a PR).
- **E2E scenarios:** `widget-pinned-sri-loads` (static fixture page with §C snippet against the local API → widget renders; tamper one byte in served `pointer.js` via a test middleware → browser blocks script, page has no `<pointer-feedback>` toolbar and console shows the integrity error), `widget-nonce-csp-styles` (fixture page with `style-src 'nonce-x'` → widget still styled via constructed stylesheet), `deploy-smoke-local` (`scripts/smoke-widget.sh http://localhost:8090` exits 0).

## Acceptance criteria

- [ ] `npm run build` writes `API/wwwroot/pointer.version.json` with `hash`, sizes, `sha384` integrity for both files; `pointer.js` gzip ≤ 61 440 B (report the number).
- [ ] `curl -I "$S/pointer.js?v=<hash>"` → `Cache-Control: public, max-age=31536000, immutable` both directly against the API and through Caddy in prod; `curl -I "$S/pointer.js"` → `no-cache`.
- [ ] Wrong `v` → current bytes, `no-cache`, `X-Pointer-Widget-Version-Mismatch` present.
- [ ] Pinned SRI snippet from `pointer init --pin` loads and runs the widget; a modified served file is blocked by the browser.
- [ ] Widget renders correctly on a page with nonce-strict `style-src` (fallback path) and unchanged on allowlist pages.
- [ ] `widget-check.yml` fails on stale artifacts and on budget breach; passes on `main`.
- [ ] `scripts/smoke-widget.sh` passes against local and production after deploy; `GET /api/meta.widgetVersion == pointer.version.json.hash`.
- [ ] Extension still loads the widget (manual check: activate on a site, toolbar appears).

## Rollout / compatibility

- Default (`/pointer.js`) behaviour is unchanged; all existing embeds keep auto-updating.
- Hosts that pin + SRI must update the snippet on each widget release (`doctor` warns). Document clearly; this is opt-in.
- Caddy change must deploy together with the API change (otherwise `?v=` requests get `no-cache` — harmless).
- `pointer.version.json` must be committed with every widget build; the CI freshness check enforces it.
