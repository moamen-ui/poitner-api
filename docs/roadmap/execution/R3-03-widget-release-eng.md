# R3-03 — Widget release engineering (content-addressed serving, SRI, size budget, deploy smoke, CSP)

(NEW-3, absorbs §22 + §34 · Release 3 · 5–7 days)

## Goal

`pointer.js` is loaded by every customer page straight from the API; today a bad deploy reaches
all of them at once and nothing measures the widget's weight. After this item: hosts can **pin** a
build with a content-addressed URL + SRI that keeps working across the next ~10 releases, the
default **latest** path stays self-updating, every build is described by a committed
`pointer.version.json`, CI fails when the bundle exceeds **60 KB gzip** or the committed artifacts are
stale, a post-deploy smoke script proves the served widget matches the build, and nonce-strict CSP
hosts get a documented, working stylesheet path. It also introduces the widget's first unit-test
harness (vitest + jsdom), which R3-04 builds on.

## Out of scope

- Unlimited build history (we retain the **last 10**; older pinned hashes 404 — see §A).
- Minifying `pointer.js` (kept readable on purpose — `web-component/build.mjs:27-29`). Revisit only if the gzip budget is hit.
- Widget kill switch (§40, held) and versioning of `skill.md` (R2-03).
- Extension changes beyond reading `pointer.version.json` (it loads `${server}/pointer.js` — `extension/src/inject-main.ts:~92` — and keeps doing so).

## Prerequisites

- None hard. Pairs with **R1-04** (`GET /api/meta` gains `widgetVersion`; if R1-04 is unmerged the smoke script skips that check with a warning) and **R1-02** (`init --pin` writes the SRI snippet for static hosts).
- Facts: static serving sets `Cache-Control: no-cache` for `pointer.js`/`pointer.css` only (`API/Program.cs:239-256`); Caddy adds `no-cache, must-revalidate` for `/pointer.js /pointer.css /embed.js /skill.md /api/branding` (`Caddyfile` `@widget` block, `:29-30`); build is `web-component/build.mjs` (esbuild IIFE, `BANNER`, unminified; sass → `pointer.css`); sibling asset URLs are resolved from `document.currentScript.src` (`web-component/src/constants.ts:153-162`) — a `?v=` query on the script URL does not affect `new URL('pointer.css', SCRIPT_SRC)`; the stylesheet is a `<link>` appended into the shadow root (`web-component/src/element.ts:186-191`) and `_stylesReady()` (`element.ts:302-312`) resolves on `load`, `error` or a 1500 ms timer; snapdom (126 KB) is lazy-loaded at capture time (`capture.ts:24-40`) and is **not** in the budget; only `publish-clients.yml` exists under `.github/workflows/`; the Docker image bakes `wwwroot` (`Dockerfile:8-13`); **`web-component/package.json` has no test framework** (scripts: build/watch/typecheck only).

## Design

### A. URL & cache scheme — content-addressed, retained history

| Request | Behaviour | Headers |
|---|---|---|
| `GET /pointer.js` (and `.css`) | **latest** — unchanged bytes of the current build | `Cache-Control: no-cache` + ETag (API) / `no-cache, must-revalidate` (Caddy) |
| `GET /pointer.js?v=<hash>` where `<hash>` ∈ retained builds | **pinned, immutable** — the **exact bytes of that build**, served from `API/wwwroot/widget/<hash>/pointer.js` | `Cache-Control: public, max-age=31536000, immutable` |
| `GET /pointer.js?v=<hash>` unknown / pruned | **404** (never the current bytes — an SRI-pinned host would be silently killed by a hash mismatch; an explicit 404 is diagnosable) | `X-Pointer-Widget-Version-Mismatch: <current hash>` |
| `GET /pointer.js?v=stable` | **stable channel** = current bytes with 1 h TTL | `Cache-Control: public, max-age=3600` |
| `GET /pointer.version.json` | build descriptor (§B) | `no-cache` |

- `<hash>` = first 12 hex of SHA-256 over the built `pointer.js` bytes (computed by `build.mjs`). CSS uses the same `v` value (one build = one hash); each file has its own `integrity`.
- **Retention:** `build.mjs` writes the bare `API/wwwroot/pointer.{js,css}` **and** `API/wwwroot/widget/<hash>/pointer.{js,css}`; it then prunes `widget/` to the **10 newest** directories listed in `pointer.version.json.retained` (order = build order). These directories are **committed artifacts** (~1.2 MB total at today's sizes). A pinned host therefore keeps working across ~10 widget releases; `pointer doctor --pin-snippet` warns when the pinned hash is no longer the newest and errors when it is no longer retained.
- **Missing/corrupt `pointer.version.json` or `widget/` dir at startup:** log once at Warning, treat **every** `?v=<hash>` as unknown (404 + mismatch header with `current=unknown`), keep serving the bare files; never 500.
- **Decision — Caddy:** the `@widget` matcher must not clobber the immutable header:
  ```
  @widget {
      path /pointer.js /pointer.css /embed.js /skill.md /api/branding
      not query v=*
  }
  header @widget Cache-Control "no-cache, must-revalidate"
  ```
  so requests with `?v=` fall through to the API's headers.

### B. `API/wwwroot/pointer.version.json` (generated by `build.mjs`, committed)

```json
{
  "version": "0.1.0",
  "hash": "9f1c2a7b3e4d",
  "commit": "3f2a9c1e",
  "committedAt": "2026-09-11T10:40:12Z",
  "files": {
    "pointer.js":  { "bytes": 118765, "gzipBytes": 31240, "integrity": "sha384-…" },
    "pointer.css": { "bytes": 19491,  "gzipBytes": 4210,  "integrity": "sha384-…" }
  },
  "retained": [
    { "hash": "9f1c2a7b3e4d", "version": "0.1.0", "files": { "pointer.js": { "integrity": "sha384-…" }, "pointer.css": { "integrity": "sha384-…" } } },
    { "hash": "5d0e…", "version": "0.0.9", "files": { … } }
  ],
  "budget": { "pointerJsGzipMax": 61440 }
}
```
- `version` = `web-component/package.json` version (bump on every widget-affecting PR — add to the widget checklist in `AGENTS.md`).
- **No wall-clock `builtAt`.** `commit`/`committedAt` come from `git log -1 --format=%h,%cI -- web-component/src` (the last commit touching the widget source), so rebuilding an unchanged tree produces a byte-identical file and the CI freshness check (§D.2) can pass. If git is unavailable (Docker build), keep the committed values (`build.mjs` reads the existing file and only rewrites when `hash` changes).
- `GET /api/meta` (R1-04) returns `widgetVersion: <hash>` read from this file at startup.

### C. SRI snippet (static hosts, opt-in)

```html
<script src="https://<server>/pointer.js?v=9f1c2a7b3e4d"
        integrity="sha384-…" crossorigin="anonymous" defer></script>
<pointer-feedback project="…" server="https://<server>" environment="staging"></pointer-feedback>
```
Emitted by `pointer init --pin` (static/Vite `index.html` only) and printed by `pointer doctor --pin-snippet`. `embed.js` stays unpinned (latest). The widget itself must load `pointer.css` with the same `?v=`: in `constants.ts`, propagate the `v` query from `SCRIPT_SRC` to `CSS_URL` (`SNAPDOM_URL` unchanged — snapdom is vendored and rarely changes). The pinned CSS `<link>` created by the widget gets `integrity` from `pointer.version.json.retained[hash].files["pointer.css"].integrity`, embedded into `pointer.js` at build time as `CSS_INTEGRITY` (so the widget does not need a network round-trip to know it).

### D. Size budget + artifact freshness (CI)

New workflow `.github/workflows/widget-check.yml` (on PR/push touching `web-component/**` or `API/wwwroot/pointer.*` or `API/wwwroot/widget/**`):
1. `npm ci && npm run typecheck && npm test && npm run build` in `web-component/`.
2. `git diff --exit-code -- API/wwwroot/pointer.js API/wwwroot/pointer.css API/wwwroot/pointer.version.json API/wwwroot/widget` → fails with "committed widget artifacts are stale — run npm run build". (Passes for an unchanged tree because §B has no wall-clock field.)
3. `node scripts/check-budget.mjs` → fails if `files["pointer.js"].gzipBytes > budget.pointerJsGzipMax` (**61 440 B = 60 KB**).
4. Boot-time perf guard: `node scripts/perf-init.mjs` — Playwright loads `e2e/fixture-app/smoke` twice, **without** and **with** the built widget, wrapping widget boot in `performance.mark('pf:boot:start'/'pf:boot:end')` (marks added to `element.ts` `connectedCallback` start / first render end) and collecting `longtask` entries between the marks; metric = long-task total (with) − long-task total (without), median of 5 runs. **Decision — thresholds & gating:** on `pull_request` the step is **warn-only** (job annotation); on `main` pushes and the nightly schedule it **fails at > 60 ms** and warns at 50–60 ms — but the hard-fail is enabled by a workflow input `PERF_HARD_FAIL=true` that is flipped on only after the guard has been green on ≥ 2 consecutive weeks of scheduled `main` runs (CI noise characterised). Record the flip date in `AGENTS.md`.

`build.mjs` computes gzip sizes (`node:zlib.gzipSync`) and integrity (`sha384` base64), writes §B, prunes `widget/`, and **fails the build locally** on budget breach (same rule as CI).

### E. Deploy smoke (`e2e/scripts/smoke-widget.sh <server>`)

Checks, each must pass: `GET /pointer.version.json` 200 → `hash`; `GET /pointer.js` 200, first line contains the `BANNER`, SHA-256[0..12] == `hash`; `GET /pointer.js?v=<hash>` returns the same bytes with `Cache-Control: … immutable`; `GET /pointer.js?v=000000000000` → 404 with `X-Pointer-Widget-Version-Mismatch`; `GET /pointer.css` 200; `GET /embed.js?project=smoke` 200 and contains `pointer-feedback`; `GET /api/branding` 200; `GET /api/meta` `widgetVersion == hash` — **skipped with a printed warning if `/api/meta` returns 404** (R1-04 unmerged). Wired into `DEPLOY.md` as the last step (`bash e2e/scripts/smoke-widget.sh https://api.<domain>`), and into `e2e/run-e2e.sh` against the local stack.

### F. CSP for nonce-strict hosts

- Allowlist hosts (the common case) are already documented (`pointer-init.md:170-189`): `script-src`, `style-src`, `connect-src`, `img-src` include the server origin — unchanged.
- Nonce-strict `style-src` blocks a runtime `<link>`. **Decision:** in `element.ts` keep the `<link>` first; **only the link's `error` event** starts the fallback (the existing 1500 ms timer in `_stylesReady`, `element.ts:302-312`, only stops waiting — it must **not** trigger the fallback, or a slow-but-working link would double-load): `fetch(CSS_URL, { integrity: CSS_INTEGRITY, mode: 'cors' })` (integrity passed so an SRI-pinned host keeps its guarantee on the fallback path; `CSS_INTEGRITY` is empty for unpinned loads and then omitted) → `new CSSStyleSheet().replace(text)` → `this.root.adoptedStyleSheets = [sheet]` (**`shadowRoot.adoptedStyleSheets`**, not `document.adoptedStyleSheets` — the styles live in the shadow root). Constructed stylesheets are not governed by `style-src`; the fetch is covered by `connect-src`, which the host must already allow for the API. Scripts (`pointer.js`, lazy snapdom) still require the origin in `script-src` — no nonce-only solution without host cooperation; document that in `pointer-init.md` ("CSP" subsection) with the two working host configurations.

### G. Widget unit-test harness (new, owned here)

Add to `web-component/`: `vitest` + `jsdom` dev-dependencies, `vitest.config.ts` (`environment: 'jsdom'`), `"test": "vitest run"` script, `src/**/*.test.ts` pattern. First tests are this doc's (`constants.test.ts`, `stylesheet-fallback.test.ts`). R3-04 adds `snapshot.test.ts` on top. `01-OVERVIEW.md` DoD references this.

## Tasks

1. `web-component/build.mjs` — after JS+CSS build: compute bytes/gzipBytes/sha384 integrity/`hash`; write `../API/wwwroot/widget/<hash>/pointer.{js,css}`; update `../API/wwwroot/pointer.version.json` (§B, `commit`/`committedAt` from git, no wall-clock); prune `widget/` to 10 newest; enforce `pointerJsGzipMax`; embed `CSS_INTEGRITY` via esbuild `define`; print a one-line size report. Add `scripts/check-budget.mjs` (reads the JSON, exits 1 on breach) and `scripts/perf-init.mjs` (§D.4).
2. `web-component/package.json` + `vitest.config.ts` — §G harness; `npm test` green with zero tests before adding any.
3. `web-component/src/constants.ts` — derive `CSS_URL` with the same `?v=` as `SCRIPT_SRC` when present; export `CSS_INTEGRITY` (build-time define, default `''`).
4. `web-component/src/element.ts:186-191, 302-312` — set `integrity`/`crossorigin` on the CSS `<link>` when `CSS_INTEGRITY` is non-empty; stylesheet fallback on `error` only (§F); `performance.mark` boot markers (§D.4). `npm run build`; commit artifacts, `widget/<hash>/`, `pointer.version.json`.
5. `API/Program.cs:239-256` — `WidgetVersionInfo` singleton loaded once at startup from `pointer.version.json` (+ existence check of each retained dir; missing → drop from the in-memory set and log); in the static-file pipeline: if `v` query present → `stable` → current bytes + 1 h; retained hash → rewrite the physical path to `wwwroot/widget/<hash>/<file>` and set immutable headers; otherwise 404 + `X-Pointer-Widget-Version-Mismatch`. Serve `/pointer.version.json` with `no-cache`. Never throw on a malformed `v` (treat as unknown).
6. `API/Controllers/MetaController.cs` (R1-04) — add `widgetVersion` from the singleton (if R1-04 not yet merged, add the field in that doc's DTO instead and note it).
7. `Caddyfile` — `@widget` matcher with `not query v=*` (§A).
8. `e2e/scripts/smoke-widget.sh` (§E, incl. the 404 check and the `/api/meta` skip); `DEPLOY.md` — final step; `e2e/run-e2e.sh` — call it against `http://localhost:8090` after reset.
9. `.github/workflows/widget-check.yml` (§D) with the `PERF_HARD_FAIL` input defaulting to `false`.
10. `cli/src/commands/init.ts` — `--pin` (static + Vite `index.html`: emit §C using `pointer.version.json` from the server); `cli/src/commands/doctor.ts` — `--pin-snippet`; `doctor` warns when a pinned `v` in the host HTML ≠ server `hash` ("pinned widget 9f1c… is behind server a2b3…; update the snippet or drop `?v=`") and **errors** when the pinned `v` is not in `retained` ("pinned widget 9f1c… is no longer served (404) — update the snippet now"). **Exit codes (pinned):** the behind-warning keeps `doctor`'s exit **0**; the pruned-pin error exits **1** (a real ✘ check, per `01-OVERVIEW.md`).
11. Docs: `API/wwwroot/pointer-init.md` — "Pinning & SRI" (incl. the 10-build retention promise) and "CSP" subsections; `AGENTS.md` — widget checklist (bump version, run build, commit `pointer.version.json` + `widget/<hash>/`, `npm test`); `web-component/README` (if present) — budget rule.

## Tests

- **Unit (API, xUnit):** `WidgetCacheHeadersTests` — `/pointer.js` → `no-cache`; `?v=<current>` → immutable + bytes equal to `widget/<current>/pointer.js`; `?v=<older retained>` → immutable + **older** bytes; `?v=wrong` → 404 + mismatch header; `?v=stable` → `max-age=3600`; malformed `v` (`../`, 200 chars) → 404, no exception; `/pointer.version.json` served; corrupt version file → bare files still served, all `?v=` 404. `MetaWidgetVersionTests` — `widgetVersion` equals the file's `hash`.
- **Unit (widget, vitest + jsdom — §G):** `constants.test.ts` — `CSS_URL` inherits `?v=`; `stylesheet-fallback.test.ts` — link `error` → fetch called with `integrity` and `adoptedStyleSheets` set on the shadow root; link `load` → no fetch; timer expiry without `error` → no fetch (stubbed `CSSStyleSheet`).
- **Build:** `check-budget.mjs` fails on a fixture JSON over budget; running `npm run build` twice on an unchanged tree yields `git diff --exit-code` clean; `widget-check.yml` fails on stale artifacts (simulate by editing `pointer.js` in a PR).
- **Caddy:** `caddy validate --config Caddyfile` in CI plus a local container (`caddy:2-alpine` with the prod `Caddyfile`, upstream = local API) asserting the header matrix through Caddy; prod `curl -I` evidence goes in the report **after** merge.
- **E2E scenarios:** `widget-pinned-sri-loads` (static fixture page with §C snippet against the local API → widget renders; tamper one byte in the served retained file via a test middleware → browser blocks script, page has no `<pointer-feedback>` toolbar and console shows the integrity error), `widget-pinned-older-build` (pin the previous retained hash → widget loads that build's bytes), `widget-pinned-unknown-404` (pin `000000000000` → 404, no widget, console shows the 404 not an SRI error), `widget-nonce-csp-styles` (fixture page with `style-src 'nonce-x'` → widget still styled via constructed stylesheet), `deploy-smoke-local` (`scripts/smoke-widget.sh http://localhost:8090` exits 0).

## Acceptance criteria

- [ ] `npm run build` writes `API/wwwroot/pointer.version.json` with `hash`, sizes, `sha384` integrity, `retained` (≤ 10) and creates `API/wwwroot/widget/<hash>/`; `pointer.js` gzip ≤ 61 440 B (report the number); a second build on the same tree is a no-op (`git status` clean).
- [ ] `curl -I "$S/pointer.js?v=<hash>"` → `Cache-Control: public, max-age=31536000, immutable`, directly against the API and through the local Caddy container; `curl -I "$S/pointer.js"` → `no-cache`.
- [ ] `curl -sD- "$S/pointer.js?v=<older retained hash>"` returns that build's bytes (sha256 matches `widget/<hash>/pointer.js`); unknown `v` → 404 + `X-Pointer-Widget-Version-Mismatch: <current>`.
- [ ] Pinned SRI snippet from `pointer init --pin` loads and runs the widget; a modified served file is blocked by the browser; after a new widget build the old pin still works (older retained bytes).
- [ ] Widget renders correctly on a page with nonce-strict `style-src` (fallback path, with `integrity` preserved when pinned) and unchanged on allowlist pages.
- [ ] `widget-check.yml` fails on stale artifacts and on budget breach; passes on `main`; perf guard produces the metric in the job summary.
- [ ] `scripts/smoke-widget.sh` passes against local (and against production after deploy — pasted in the report); `GET /api/meta.widgetVersion == pointer.version.json.hash`.
- [ ] `npm test` in `web-component/` runs the two new test files green.
- [ ] Extension still loads the widget (manual check: activate on a site, toolbar appears).

## Rollout / compatibility

- Default (`/pointer.js`) behaviour is unchanged; all existing embeds keep auto-updating.
- Hosts that pin + SRI keep working for the next ~10 widget releases; `doctor` warns when behind and errors when pruned. Document clearly; pinning is opt-in.
- Caddy change must deploy together with the API change (otherwise `?v=` requests get `no-cache` — harmless).
- `pointer.version.json` and `widget/<hash>/` must be committed with every widget build; the CI freshness check enforces it. Repo growth ≈ 140 KB per release, capped by pruning.
